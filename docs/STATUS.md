# Статус «Подхода»

## Этап 4: файловые резервные копии

- В настройках можно подготовить зашифрованную копию всего журнала, скачать её или передать через системное меню, если браузер поддерживает отправку файлов. Пароль не сохраняется. Открытие меню не подтверждает доставку. Журнал напоминает о копии при открытии, если отметки нет или прошло семь дней.
- Восстановление работает без сети: после проверки пароля, формата и связей показываются дата и сводка, предупреждение о полной замене и предложение сначала выгрузить текущий журнал. Данные и оформление заменяются одной транзакцией IndexedDB v4. Обновление базы сохраняет прежние записи и настройки оформления. Лимит файла: 16 МиБ.
- Прошли 101 тест Vitest, проверка типов, сборка, независимое ревью и приёмка. В Edge при 390 × 844 проверены скачивание, перенос без сети в отдельный браузерный профиль, отказ при неверном пароле и повреждении файла, предупреждение и подтверждение замены, сохранность после перезагрузки и напоминание на седьмой день. Web Share проверен через имитацию API; физические телефоны, Telegram, облака и GitHub Pages не проверялись.
- Следующий этап после отправки этого коммита в `origin/main`: 5, установка PWA и публикация на GitHub Pages. Не начат.

## Этап 3: заморозка абонементов

- В карточке можно запланировать паузу и закончить её в день досрочного возвращения. Пока действует пауза, статус и дата возвращения видны в карточке и списке клиентов. В архиве история доступна только для чтения.
- День возвращения не входит в паузу. Сдвигаются календарные границы затронутого и уже оформленных следующих периодов, но не платежи и начисления. IndexedDB v3 сохраняет прежние записи.
- При локальной проверке прошли 79 тестов, проверка типов и сборка. В Edge при 390 × 844 проверены пауза 5→10, возврат 8-го, запрет пересечений и начала вне периода, сдвиг оплаченного продления без новых взносов и сохранение в архиве после перезапуска. На физическом телефоне и GitHub Pages не проверялось.
- Независимое ревью и приёмка пройдены. Этап закрыт после отправки коммита с этой записью в `origin/main`. Следующий этап: 4, файловые бэкапы; не начат.

## Этап 2: тарифы, абонементы и платежи

- Реализованы настройки тарифов, оформление, перенос и продление абонемента, журнал взносов и исправление суммы платежа без изменения дат. Доплата не продлевает период. Отключение и изменение тарифа не меняют историю.
- IndexedDB v2 сохраняет карточки из v1; архив сохраняет связанные записи, удаление убирает их вместе с карточкой.
- Проверены расчёт конца месяца, раннее и позднее продление, бесплатный тариф, перенос без начисления, сортировка, запрет переплаты, исправление платежа, архив и сохранение после перезапуска Edge на ширине 390 px. На физическом телефоне и GitHub Pages не проверялось.
- Тесты, сборка, проверка типов, ревью и приёмка пройдены; этап отправлен в `origin/main`.

## Этап 1: клиенты

- Последний проверенный этап: 1, репозиторий, документация и клиенты (25.11.2026).
- Реализованы список, карточка, создание клиента без абонемента, поиск, архив, возврат и удаление с подтверждением. Данные хранятся в IndexedDB v1.
- Проверки DevConductor: `npm.cmd test` (14/14), `npm.cmd run typecheck` и `npm.cmd run build` прошли. Первый запуск через `npm` без расширения не стартовал из-за выбора Windows-обёртки; команды с явным `npm.cmd` прошли. Независимое ревью и слепая приёмка пройдены.
- `npm run test:mobile -- msedge` прошёл на production-сборке в эмуляции 390 × 844: пустая и заполненная карточки, префиксный поиск, архив, возврат, отмена, одиночное, массовое и архивное удаление, перезапуск браузера с сохранением данных. Реальные телефоны и Pages не проверялись.
- Этап 1 отправлен в `origin/main` ([коммит `5372cb7`](https://github.com/tmksdm/podhod/commit/5372cb72e85e447137c1751769ba3683e2878cdb)).

Локальный запуск: `npm ci`, затем `npm run dev -- --host 127.0.0.1`. Открывайте адрес с `127.0.0.1` из вывода Vite: у `localhost` отдельная база. Для мобильного сценария сначала `npm run build`, затем `npm run test:mobile -- msedge` при установленном Microsoft Edge.

Идеи на будущее, не требования этапа 1: отдельный демонстрационный набор вымышленных клиентов для ручной проверки статусов только в режиме разработки, без записи в рабочий журнал; иконка этапа 5 на основе знака из шапки (три тёмные полосы по возрастанию на жёлтом фоне).
