# Статус «Подхода»

## Этап 2: тарифы, абонементы и платежи

- Реализованы настройки тарифов, оформление, перенос и продление абонемента, журнал взносов и исправление суммы платежа без изменения дат. Доплата не продлевает период. Отключение и изменение тарифа не меняют историю.
- IndexedDB v2 сохраняет карточки из v1; архив сохраняет связанные записи, удаление убирает их вместе с карточкой.
- Проверены расчёт конца месяца, раннее и позднее продление, бесплатный тариф, перенос без начисления, сортировка, запрет переплаты, исправление платежа, архив и сохранение после перезапуска Edge на ширине 390 px. На физическом телефоне и GitHub Pages не проверялось.
- Этап закрыт, когда коммит с этой записью есть в `origin/main` и прошли тесты, сборка, проверка типов, ревью и приёмка. Следующий этап: 3, заморозка; не начат.

## Этап 1: клиенты

- Последний проверенный этап: 1, репозиторий, документация и клиенты (25.11.2026).
- Реализованы список, карточка, создание клиента без абонемента, поиск, архив, возврат и удаление с подтверждением. Данные хранятся в IndexedDB v1.
- Проверки DevConductor: `npm.cmd test` (14/14), `npm.cmd run typecheck` и `npm.cmd run build` прошли. Первый запуск через `npm` без расширения не стартовал из-за выбора Windows-обёртки; команды с явным `npm.cmd` прошли. Независимое ревью и слепая приёмка пройдены.
- `npm run test:mobile -- msedge` прошёл на production-сборке в эмуляции 390 × 844: пустая и заполненная карточки, префиксный поиск, архив, возврат, отмена, одиночное, массовое и архивное удаление, перезапуск браузера с сохранением данных. Реальные телефоны и Pages не проверялись.
- Этап 1 отправлен в `origin/main` ([коммит `5372cb7`](https://github.com/tmksdm/podhod/commit/5372cb72e85e447137c1751769ba3683e2878cdb)).

Локальный запуск: `npm ci`, затем `npm run dev -- --host 127.0.0.1`. Открывайте адрес с `127.0.0.1` из вывода Vite: у `localhost` отдельная база. Для мобильного сценария сначала `npm run build`, затем `npm run test:mobile -- msedge` при установленном Microsoft Edge.

Идеи на будущее, не требования этапа 1: отдельный демонстрационный набор вымышленных клиентов для ручной проверки статусов только в режиме разработки, без записи в рабочий журнал; иконка этапа 5 на основе знака из шапки (три тёмные полосы по возрастанию на жёлтом фоне).
